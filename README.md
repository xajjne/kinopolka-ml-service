<h1 align="center">Сервис эмбеддингов Кинополки</h1>
<p align="center">Описания фильмов и запросы зрителей в одном векторном пространстве.</p>

Сервис превращает текст в нормализованный вектор из **1024 чисел** с помощью модели **BAAI/bge-m3**. Описания каталога обрабатываются заранее, а фраза зрителя — при поиске. Благодаря общей модели PostgreSQL может сравнить запрос «экспедиция в дальний космос» с описаниями фильмов по косинусному расстоянию.

## Возможности

| Задача | Как устроена |
| --- | --- |
| Подготовить модель | Загрузчик сохраняет фиксированную ревизию BGE-M3 и метаданные в `models/bge-m3`. При последующих запусках модель читается с диска. |
| Векторизовать каталог | Для каждого произведения скрипт объединяет название, оригинальное название, описание, жанры и ключевые слова. Карточки без описания пропускаются. |
| Обновить каталог | Скрипт сверяет SHA-256 текста, версию его формата и ревизию модели. Повторный запуск пересчитывает новые и изменившиеся записи. |
| Обработать запрос зрителя | FastAPI возвращает вектор текста и сведения о модели. Бэкенд использует этот вектор для поиска соседей в PostgreSQL. |
| Оценить точность HNSW | Бенчмарк сравнивает десятку ближайших соседей с точным поиском и измеряет время SQL-запроса при разных значениях `ef_search`. |

## Стек

**Python · Sentence Transformers · PyTorch · FastAPI · Uvicorn · psycopg · PostgreSQL с pgvector**

## Локальный запуск

Пример для PowerShell и Python 3.13. Команды выполняются из корня репозитория. Для проверки HTTP API достаточно установить зависимости и скачать модель. PostgreSQL понадобится на этапе векторизации каталога и при запуске бенчмарка.

**1. Создайте окружение.**

```powershell
python -m venv .venv
```

**2. Выберите одну сборку PyTorch** в зависимости от оборудования.

Для NVIDIA с поддержкой CUDA 12.6:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-cuda.txt
```

Для CPU:

```powershell
.\.venv\Scripts\python.exe -m pip install torch==2.9.1 --index-url https://download.pytorch.org/whl/cpu
```

**3. Установите остальные зависимости и один раз скачайте модель с Hugging Face.**

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe download_model.py
```

**4. Запустите API.** Один рабочий процесс загружает одну копию модели. При старте сервис выбирает CUDA, если она доступна, иначе CPU.

```powershell
.\.venv\Scripts\python.exe -m uvicorn api:app --host 127.0.0.1 --port 8000 --workers 1
```

## Первый запрос

В отдельном окне PowerShell проверьте готовность модели и отправьте текст. Пример выводит размерность и первые пять координат вектора.

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health

$body = @{ text = 'Научная фантастика о первом контакте' } | ConvertTo-Json
$result = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/embed -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body))
$result.embedding.Count
$result.embedding | Select-Object -First 5
```

Ожидаемая размерность — `1024`. Маршрут `POST /embed` принимает текст длиной от 1 до 1000 символов. Если модель уже обрабатывает запрос, сервис возвращает HTTP 503. Интерактивная документация открывается по адресу `http://127.0.0.1:8000/docs`.

## Векторизация каталога

Сначала примените миграции и импортируйте фильмы в [бэкенде Кинополки](https://github.com/xajjne/kinopolka-backend). По умолчанию скрипт читает параметры PostgreSQL из `../backend/.env`. При другой структуре папок передайте путь через `--env-file`.

```powershell
.\.venv\Scripts\python.exe embed_titles.py
```

Скрипт записывает векторы в `title_embeddings`. Перед записью он повторно проверяет текст карточки. Если описание успело измениться во время вычисления, карточка будет обработана при следующем запуске. [SQL для подготовки текста](sql/embedding-source.sql)

## Проверка поиска HNSW

Бенчмарку нужны работающий HTTP API, PostgreSQL и минимум десять совместимых эмбеддингов. Команда сохраняет результаты в текущую папку:

```powershell
.\.venv\Scripts\python.exe benchmark_hnsw.py --output hnsw.json
```

**Recall@10** показывает, сколько из десяти точных ближайших соседей нашёл HNSW: например, девять совпадений дают 0,9. Отчёт позволяет сравнить точность и скорость при `ef_search` 20, 40, 100 и 200. Время измеряется для SQL на прогретом кеше базы, отдельно от вычисления вектора запроса. [Код бенчмарка](benchmark_hnsw.py)
